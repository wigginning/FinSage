# FinSage 安全模型

> English: see [`security.md`](security.md)

本文档陈述 FinSage 的安全模型与信任边界，将前端安全契约（§26.16）与 `AGENTS.md` 的安全规则（§31.7 等价条款）整合为单一可操作参考。

## 1. 信任边界

```text
[ 用户浏览器 ] ──┬─ 可信：HTTP + 签发/校验的令牌
                 │
[ apps/api ] ────┴─ 可信的来源边界
        │  可信：内部类型化接口（OpenAPI 契约）
        ├── [ 模型 / 内部服务 ]               可信代码 + 资源（模型只读）
        ├── [ Provider（AKShare/BaoStock/yfinance）] 半可信：一律校验并归一化
        └── [ 检索到的文档 / 网页内容 ]       始终是不可信输入
```

- **信任凭据**绝不允许嵌入源码、日志、镜像或客户端 bundle。
- **外部文档/网页内容是不可信的**：仅作为数据解析、绝不执行、绝不允许覆盖系统指令（提示注入防御）。

## 2. 前端安全契约（§26.16）

- Token/会话值**绝不**写入源码。
- **API key 绝不进入客户端 bundle**；只在服务端配置。
- **不信任外部内容渲染出的 Markdown/HTML**；输出时清洗/转义。
- **证据文本默认按纯文本渲染**，中和内嵌的 HTML/脚本。
- **外部链接**以安全策略打开（`rel="noopener noreferrer"`）。
- **绝不向客户端暴露后端原始堆栈**；错误映射为稳定的 `FIN-XXXX` 编码与用户安全消息。

## 3. 服务端与数据安全（§31.7）

- **绝不提交 API key。** 仅 `.env.example` / `.env.local.example` 样例入库；`.env.*` 被 git 忽略。
- **绝不记录密钥。** 输入/输出遥测不包含凭据与令牌。
- **密钥绝不写入审计存储。** `AuditEntry` 只捕获模型/工具/Provider 与运维元数据——敏感值在构造上即被排除。
- **最小权限。** 服务账号只授予其所需的数据库/对象/权限范围；`docker-compose.yml` 中的默认 `FIN_DB_USER`/口令**仅限本地开发**，任何真实部署必须经环境变量替换。

## 4. 运行时卫生

- 全部中间件为 async，不用回调风格（保持错误/清理路径确定性）。
- 追踪 ID（`X-Trace-Id`）随请求传播；检索保留 `document_id`/`chunk_id`/来源，使每个结论可溯源。
- 政策门控拦截越权与敏感输出；核验防止无支撑结论以高置信事实的面目出现。
- 财务数字来自确定性引擎，因此算术层面的暴露面是代码，而非模型推理。

## 5. 上报

安全敏感变更与架构变更一样须经 ADR 评审——任何信任边界的变更必须先有 Accepted ADR 才能实施。
