# FinSage Evaluation (FinEval)

> 中文版：请见 [`benchmark.zh-CN.md`](benchmark.zh-CN.md)

This document describes the FinEval benchmark suite and how to run/report it. It follows the
honesty rules of `AGENTS.md` (§10 / §31.10): **benchmark results are produced only by actually
running the suite with a configured executor; fabricated or self-rated numbers are forbidden.**

## 1. What FinEval provides

- A **deterministic dataset** — `finsage-bench` v3.4, exactly **100 cases**, evenly split across five
  task types (20 each):
  - `retrieval` — expected source documents should be recalled;
  - `numeric` — financial arithmetic matches a deterministic expectation (covering negative/zero
    denominator edge cases);
  - `citation` — answers must cite the right evidence;
  - `abstention` — missing evidence must yield an abstention rather than a confident guess;
  - `provider_reliability` — expected behavior around source/provider conflicts and reliability.

  Expected values are deterministic (never generated by an LLM and never bound to live quotes).

- **Evaluators** (one per task type) and a **`BenchmarkRunner`** that executes cases with an
  injected executor, aggregates metrics, and can persist results.

- **Reproducibility metadata** (`RunMetadata`): `git_commit` (best-effort, `"unknown"` when not in a
  git repo), `model_name`, `embedding_model`, `reranker_model`, and `config`.

## 2. How scoring works

`BenchmarkRunner.run(spec)` loops each case, obtains the deterministic result via the injected
`CaseExecutor`, scores it with the type's evaluator, and aggregates:

```text
overall: total / passed / pass_rate / avg_score
per_type: {retrieval, numeric, citation, abstention, provider_reliability} → same metrics
```

Metrics are computed **only from actual outcomes** — never invented and never averaged by an LLM.

## 3. Running a benchmark

Scoring a real benchmark requires a `CaseExecutor` wired to the production workflow (m06 graphs
+ models + provider registry). DB persistence is optional via an `EvaluationStore`. Because that
executor depends on configured models/infra, **no production benchmark numbers are claimed in this
repository yet.**

To add a runner entry point, build the dataset with `build_benchmark()` and invoke the runner:

```python
import asyncio
from finsage.evaluation.benchmarks import build_benchmark
from finsage.evaluation.runner import BenchmarkRunner

async def main():
    spec = build_benchmark()                 # finsage-bench, v3.4-100cases
    executor = ...                           # adapter over the production m06 workflow
    report = await BenchmarkRunner(executor).run(spec)
    print(report.metrics)

asyncio.run(main())
```

Record the report's `RunMetadata` (model names, git commit, config) so a result can be reproduced.

## 4. Honesty rules

- Report only numbers produced by an actual run with a real executor.
- Never mark a case passed unless the deterministic evaluator says so.
- When a task's expected behavior cannot be evaluated (unknown `task_type`), skip it — do not count
  it, do not invent a score (No-Guess).
- Keep the exact dataset version and `RunMetadata` alongside any published number.

## 5. Test status of the framework itself

The infrastructure is covered by `tests/evaluation/test_evaluation.py` (deterministic evaluator +
runner behavior, using synthetic perfect/failing executors). These framework tests pass in CI; they
verify the machinery, not any production model quality number.
